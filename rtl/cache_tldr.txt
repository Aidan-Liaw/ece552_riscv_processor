Structure: The cache holds 32 sets, each with 2 ways, and each way holds a 16-byte cache line (4 words of 32 bits). The address is broken into a 4-bit byte offset, a 5-bit set index, and a 23-bit tag. Each set also tracks a 1-bit LRU flag and valid bits per way.
Hit path: On every cycle, the incoming address is decoded and both ways are checked simultaneously — if either way's tag matches and its valid bit is set, that's a hit. On a read hit, the correct word is returned combinationally (no stall). On a write hit, the matching cache line is updated immediately using the byte mask to merge only the requested bytes, and a write-through to backing memory is initiated. If memory happens to be busy at that moment, the write is queued in a small one-entry pending buffer (wt_pending) and drained as soon as memory becomes available.
Miss path: On a miss (read or write), the cache asserts o_busy to stall the CPU and transitions to the REFILL state. It first selects a victim way — preferring an invalid way, otherwise using the NMRU bit — then streams all 4 word requests to memory back-to-back, without waiting for each response before issuing the next one (pipelined/streaming refill). As responses arrive, each word is written directly into the victim way. The specific word originally requested by the CPU is saved so it can be returned once the refill completes.
Write-miss handling: If the original request was a write, after the refill finishes the cache enters the WRITE_THROUGH state. It merges the bytes being written into the freshly refilled word using the byte mask, updates the cache line, and then writes the merged word out to backing memory. This is the write-allocate behavior — the line is brought in first, then the write is applied to both cache and memory.
Replacement: The LRU bit per set tracks which way was most recently used. On any hit or completed refill, the LRU bit is updated so the other way becomes the eviction candidate next time.
